Self-attention lets every token in a sequence look directly at every other token and decide how
much to "borrow" from it when updating its own meaning. Concretely, each token's embedding is
projected through three separate learned weight matrices into three vectors:

- **Query (Q)** — what this token is "looking for" in the rest of the sequence.
- **Key (K)** — what this token "advertises" about itself, i.e. what it can be matched against.
- **Value (V)** — the actual content this token contributes if it turns out to be relevant.

Relevance between token *i* and token *j* is the dot product of query *i* and key *j* — a
larger dot product means stronger alignment. Because dot products over a *d_k*-dimensional
space grow in magnitude as *d_k* grows, the raw scores are divided by √*d_k* before softmax —
without this scaling, large-magnitude scores push softmax into a saturated regime with
near-zero gradients almost everywhere. After scaling, softmax turns the scores into a
probability distribution (the attention weights), and the output for token *i* is the weighted
sum of every token's value vector:

**Attention(Q, K, V) = softmax(QKᵀ / √d_k) V**

## The Q/K/V mental model

- **Query = "what am I looking for?"** — e.g. a pronoun like "it" implicitly asks "which
  earlier noun do I refer to?"
- **Key = "what do I contain / advertise?"** — e.g. a noun's key encodes "I'm a physical,
  potentially-fatiguable entity," which is what makes it a good match for "it."
- **Value = "what do I actually hand over if picked?"** — the information that gets blended
  into the querying token's new representation once a match is found.

Step by step, for a whole sequence: project all tokens into Q, K, V matrices → compute QKᵀ (an
n×n matrix of raw relevance scores) → divide by √d_k → softmax row-wise → multiply by V to get,
for every token, a context-aware blend of the tokens it attended to.

## Analogy

Think of it like a library / search-engine lookup happening simultaneously for every word in
the sentence: your **query** is the search term you type in; every book's **key** is its
title/tags; every book's **value** is its actual contents. The more your query matches a key,
the more that book's content shapes the answer — except here, every word in the sentence is
running its own search at the same time, and the "books" are the other words.

## Worked example

Sentence: **"The cat sat because it was tired."** When the model computes attention for
**"it"**, "it" generates a query roughly encoding "I'm a pronoun — which earlier noun am I
standing in for?" **"cat"**'s key strongly matches that query, while function words like "the,"
"because," "was" produce weak matches — so "it" ends up with a high attention weight on "cat."

  answer="Because dot products over d_k dimensions have variance that grows with d_k; without scaling, scores can become large in magnitude and push softmax into a region with vanishingly small gradients, hurting learning. Dividing by √d_k keeps the score magnitudes roughly constant regardless of d_k."
