A single attention layer computes one weighted average per token. That is a real limit: a token
often needs to track several different relationships at once. In *"The bank raised rates after
the flood"*, the word "bank" needs both the syntactic subject relationship and the semantic
disambiguation from "rates" versus "flood" — one set of attention weights has to pick.

Multi-head attention solves this by running attention **several times in parallel**, each in its
own lower-dimensional subspace, then concatenating the results.

## How the split works

The mechanism is simpler than it sounds. With `d_model = 128` and `num_heads = 4`:

1. Project the input into Q, K, V as usual — still `d_model` wide.
2. **Slice** each of those into 4 chunks of `d_k = d_model / num_heads = 32`.
3. Run ordinary scaled dot-product attention independently in each chunk.
4. **Concatenate** the 4 outputs back to 128 dims.
5. Apply one final output projection `W_o`.

Note what this does *not* cost: because the heads are slices rather than copies, total
computation is roughly the same as single-head attention over the full width. You get multiple
relationship channels for free.

Two things worth noticing while you click around:

- **Heads disagree, and that is the point.** If every head learned the same pattern, the extra
  heads would be wasted parameters. Their disagreement is the evidence that the subspaces
  captured different relationships.
- **Broad, flat attention is not a failure.** For topic classification with mean-pooling, a head
  that spreads weight evenly is effectively saying "average everything" — a genuinely useful
  operation for this task.

## Why concatenate instead of average?

A natural question: why not just average the heads? Because averaging would collapse them back
into one pattern and throw away exactly what you paid to compute. Concatenation keeps all four
results distinct, and the learned output projection `W_o` decides how to blend them — which
means the model can learn *per-dimension* how much each head should contribute, rather than
being forced into a uniform mix.

## Repo grounding

This is `MultiHeadAttention` in `mini_transformer/model/attention.py`:

- `_split_heads` reshapes `(batch, seq, d_model)` → `(batch, heads, seq, d_k)`
- `scaled_dot_product_attention` runs on all heads at once (the head axis just rides along as a
  batch dimension)
- `_merge_heads` reverses the reshape
- `self.w_o` is the final projection
- `self.attn_weights` caches the weights — which is exactly what the visualization above reads

The constructor also enforces `d_model % num_heads == 0`, the same rule your `splitHeads`
implementation had to reject.
