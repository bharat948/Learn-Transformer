Self-attention computes a weighted sum over *all* positions using only content-based similarity
(query · key). If you shuffled the words in a sentence and shuffled the attention weights the
same way, the output would just be a relabeled version of the same set of vectors — attention
has no built-in notion of "before" or "after." It's **permutation-equivariant**: it treats a
sequence as a *set* of tokens, not an ordered list.

That's a problem, because word order carries meaning ("dog bites man" vs. "man bites dog"). So
Transformers inject position information explicitly, typically by adding a position-dependent
vector to each token embedding, so each token's representation encodes both *what* it is and
*where* it is.

## Sinusoidal vs. learned vs. none

- **Sinusoidal** (`SinusoidalPositionalEncoding` in this repo's `positional.py`) — a fixed,
  non-trainable vector per position, built from sine and cosine waves of geometrically
  decreasing frequency across the embedding dimensions. Two properties made this the paper's
  choice:
  - **Relative-position linearity** — for any fixed offset `k`, `PE(pos+k)` can be written as a
    fixed linear transformation of `PE(pos)`, so the model can learn to attend by *relative*
    position.
  - **Extrapolation** — the formula is defined for any position, so it can produce encodings for
    sequence lengths longer than anything seen during training. Notably, the original paper
    also tried learned embeddings and found the two gave **"nearly identical results"**
    empirically — the choice was about extrapolation, not accuracy.
- **Learned** (`LearnedPositionalEncoding`) — a trainable `nn.Embedding(max_len, d_model)`
  lookup table, one vector per position, updated by gradient descent. This is what BERT and
  GPT-2 use. It's flexible but capped: positions beyond `max_len` (BERT-base: 512) simply have
  no learned vector.
- **None** (`NoPositionalEncoding`) — identity function, no position signal reaches the model at
  all. This is the ablation control in this repo's `ablation.py`.

## Analogy

Sinusoidal encoding is like being handed a seat badge whose color pattern is generated by a
repeating formula — anyone can compute a valid badge for *any* seat, even one that doesn't
exist yet, and nearby seats have recognizably similar badges. Learned encoding is like a seating
chart with names pre-printed on numbered placards up to seat 512 — precise for the seats that
exist, but there's no placard for seat 513.

## Worked example

Toy `d_model = 4`, using `PE(pos, 2i) = sin(pos / 10000^(2i/4))` and
`PE(pos, 2i+1) = cos(pos / 10000^(2i/4))`:

- Position 0: `[sin(0), cos(0), sin(0), cos(0)] = [0, 1, 0, 1]`
- Position 1: `≈ [0.841, 0.540, 0.010, 0.9999]`
- Position 2: `≈ [0.909, -0.416, 0.020, 0.9998]`

The first dimension pair (high frequency) changes fast between positions, while the second pair
(low frequency) barely moves — this "fast bits vs. slow bits" pattern lets the encoding
represent both fine- and coarse-grained position simultaneously.
